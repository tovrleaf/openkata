# Design

## Architecture

```
Agent → openkata.dev/mcp (Function URL)
          → Lambda (openkata-mcp)
              → S3 (skill/rule archives)
              → DynamoDB (download counts)

Browser → openkata.dev (CloudFront)
            → Lambda (openkata-web)
                → S3 (tar.gz downloads)
                → DynamoDB (download counts)
```

## S3 bucket structure

- Bucket: `openkata-artifacts`
- Public access: **blocked** (BlockPublicAccess all on)
- Access: Lambda execution roles only (via IAM policy)
- No bucket policy — access granted through role-based
  GetObject/PutObject/ListObjects permissions
- Users never access S3 directly — all reads proxied
  through Lambda

## versions.json

```json
{
  "skills": {
    "create-adr": {
      "version": "1.1.0",
      "description": "Creates Architecture Decision Records",
      "tags": "documentation, architecture"
    },
    "commit-conventions": {
      "version": "2.0.0",
      "description": "Enforces Conventional Commits format",
      "tags": "git, conventions"
    }
  },
  "rules": {
    "bash-style": {
      "version": "0.1.0",
      "description": "Bash scripting conventions",
      "tags": "bash, scripting"
    }
  }
}
```

Generated by the publish workflow from SKILL.md/RULE.md
frontmatter + git tag version.

## MCP tools

### list_skills

Returns all skills from cached `versions.json`:
name, version, description, tags, download count.

### list_rules

Same as above for rules.

### install_skill(skill, version?)

1. Resolve version (default: latest from versions.json)
2. Read all files from S3 prefix
3. Generate `.manifest.json` with checksums
4. Increment DynamoDB counter
5. Return structured response:
   ```json
   {
     "name": "create-adr",
     "version": "1.1.0",
     "manifest": { ... },
     "files": {
       "SKILL.md": "---\nname: create-adr\n...",
       "references/checklist.md": "# Checklist\n..."
     }
   }
   ```

### install_rule(rule, version?)

Same as install_skill for rules.

### skill_versions(skill)

Lists all available versions via S3 `ListObjects` on
the skill prefix. Returns array of version strings.

### rule_versions(rule)

Same as skill_versions for rules.

## CI workflows

### publish.yaml (on tag push)

Triggers on: `skills/*/v*` and `rules/*/v*` tags.

```
1. Checkout with fetch-depth: 0
2. Parse tag → artifact path + version
3. git archive <tag> -- <path> → extract files
4. Upload to S3: openkata-artifacts/<path>/<version>/
5. Regenerate versions.json from all S3 prefixes
6. Upload versions.json to S3
```

### deploy-mcp.yaml (on push to main)

```
1. Checkout (shallow)
2. Build: go build -o bin/openkata-mcp ./cmd/openkata-mcp/
3. Zip and deploy to Lambda
```

## DynamoDB table

- Table name: `openkata-downloads`
- Partition key: `artifact` (String) — e.g. `skills/create-adr`
- Attributes: `downloads` (Number)
- On install/download: `UpdateItem ADD downloads 1`
- On list: `Scan` (fine for <50 items, cached)

## Lambda configuration

- Runtime: `provided.al2023`
- Architecture: `arm64`
- Memory: 128 MB
- Reserved concurrency: 10
- Function URL: enabled, auth type NONE
- Environment: `OPENKATA_BUCKET=openkata-artifacts`,
  `OPENKATA_TABLE=openkata-downloads`

## Web download route

```
GET /skills/                       → skill listing page
GET /skills/:name                  → skill detail page
GET /skills/:name/archive          → download latest tar.gz
GET /skills/:name/archive/:version → download specific version
GET /rules/                        → rule listing page
GET /rules/:name                   → rule detail page
GET /rules/:name/archive           → download latest tar.gz
GET /rules/:name/archive/:version  → download specific version
```

Archive routes:
1. Resolve version (no segment = latest from versions.json)
2. Fetch archive from S3
3. Increment DynamoDB counter
4. Return tar.gz with Content-Disposition header

## IAM roles

### openkata-mcp-role

- S3: GetObject, ListObjects on `openkata-artifacts/*`
- DynamoDB: GetItem, UpdateItem, Scan on
  `openkata-downloads`

### openkata-web-role (extend existing)

- S3: GetObject on `openkata-artifacts/*`
- DynamoDB: GetItem, Scan on `openkata-downloads`
  (read only for display)
- DynamoDB: UpdateItem on `openkata-downloads`
  (for download counting)

### openkata-ci-role (extend existing)

- Lambda: UpdateFunctionCode on both functions
- S3: PutObject, ListObjects on `openkata-artifacts/*`
