# Create Skill

Create skills for this project. Skills can be either local
(project-internal) or distributable (shared via the dojo).

## Workflow

1. **Gather intent** — Ask the user what the skill should do.
   Collect:
   - A short name (lowercase, hyphenated, e.g., `run-tests`)
   - A one-line description
   - When the skill should activate (trigger conditions)
   - The workflow steps the skill should guide

2. **Determine placement** — Ask whether this skill is:
   - **Local** → `.agents/skills/<name>/` — internal, not
     distributed
   - **Distributable** → `skills/<name>/` — shared via the dojo

3. **Check for conflicts** — List both `.agents/skills/` and
   `skills/` to ensure the name isn't already taken.

4. **Generate SKILL.md** — Create the SKILL.md in the target
   directory using the following skeleton:

   ```markdown
   ---
   name: your-skill-name
   version: 1.0.0
   description: >
     One-sentence summary of what it does. Use when the user
     wants to <scenario>, needs to <scenario>, mentions
     <keyword>, or asks about <topic>.
   ---

   # Your Skill Name

   Brief intro sentence.

   ## Workflow

   1. **Step one** — Description.
   2. **Step two** — Description.
   ```

   Follow the style of existing skills — see `ryu-release` and
   `create-adr` for reference.

5. **Create CHANGELOG.md** — Start at v1.0.0 with an initial
   `### Added` entry.

6. **Import to Tessl** — Run
   `tessl skill import <skill-directory>` to generate `tile.json`
   (ADR 0006).

7. **Symlink if distributable** — For skills in `skills/`, ask
   the user if they want it symlinked into `.agents/skills/`. If
   yes:
   ```bash
   ln -s ../../skills/<name> .agents/skills/<name>
   ```

8. **Quality check** — Follow the `review-skill` workflow to
   lint, review, and optimize the new skill.

9. **Confirm** — Show the user the created skill and ask if
   adjustments are needed.

## Writing Principles

- **Be pushy with descriptions.** Agents undertrigger skills.
  Make descriptions slightly aggressive about when to activate —
  list many natural phrasings, including edge cases.
- **Explain the why, not rigid rules.** Reasoning is more
  effective than blunt constraints because it lets the agent apply
  intent across novel situations.

## Conventions

- Local skills go in `.agents/skills/<name>/`
- Distributable skills go in `skills/<name>/` with a symlink in
  `.agents/skills/`
- Every skill must have a `tile.json` generated by
  `tessl skill import`
- Every skill gets a CHANGELOG.md
- Keep skills focused — one skill, one job
